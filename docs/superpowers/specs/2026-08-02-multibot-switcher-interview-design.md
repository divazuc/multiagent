# מפרט: בורר בוטים בדשבורד + ראיונות העשרת ידע

**תאריך:** 2026-08-02 · **דדליין:** פגישת קרופניק היום-מחר · **סטטוס:** מאושר ע"י דיוה

## מטרה

שני פיצ'רים בדמו של אסתטיק קליניק (`bdc47180-a3c1-47d0-9a51-fea4b2830fe2`), לקראת פגישת מכירה עם ד"ר קרופניק שהצעת המחיר שלו כוללת hub + 3 בוטים ייעודיים:

1. **בורר בוטים** — הצגת שלושה בוטים (הכשרת רופאים / טיפולים אסתטיים / השתלות שיער) כ"זונים" נפרדים בדשבורד הלקוח, כשכבת תצוגה על הסיווג הקיים. בלי מודל נתונים חדש.
2. **ראיונות העשרה** — שאלות שנשאלות ברשת בתחום העסק מוצגות לבעל העסק בפורטל; הוא עונה בשפה חופשית, Claude מלטש, והתוצאה נוחתת בסטריפ אישור ההצעות הקיים.

**לא בהיקף:** מודל אמיתי של חשבון→בוטים (טבלת bots, ידע ומספרים נפרדים) — זה שלב הפרויקט של קרופניק אחרי חתימה. עמודת domain אמיתית בטבלאות — fast-follow אפשרי אחרי הפגישה.

## רקע — מה כבר קיים

- הדונאט "התפלגות תחומי פנייה" ב-Overview מסווג שיחות ל-3 תחומים עם regex עברי קשיח ב-`server/lib/studio.js` (`getOverviewStats`, `DOMAIN_TESTS`).
- `checkAndSuggestFaq` (`server/index.js`) כבר יוצר `knowledge_items` עם `suggested=true` משיחות חיות; טאב FAQ מציג סטריפ אישור עובד (אישור והוספה למאגר / דחייה).
- קונפיג פר-עסק קיים ב-`business_profiles.draft_setup_data.dashboard_config` (JSONB).
- הפורטל (`src/portal/main.jsx`) עוטף את אותו `ClientDashboard` עם התחברות; כל שינוי בדשבורד משרת גם את הדמו וגם את הפורטל.

## פיצ'ר 1: בורר בוטים

### קונפיגורציה

מערך חדש `draft_setup_data.dashboard_config.bots`:

```json
{
  "bots": [
    { "id": "doctors",    "name": "הכשרת רופאים",     "icon": "🩺", "color": "#6d28d9",
      "panel": "פאנל 01 · 972-51-555-1111", "keywords": "קורס|רופא|הכשר|סילבוס|השתלמ|בי.?ה.?ס" },
    { "id": "treatments", "name": "טיפולים אסתטיים",  "icon": "💉", "color": "#0d9488",
      "panel": "פאנל 02 · 972-51-555-2222", "keywords": null },
    { "id": "hair",       "name": "השתלות שיער",      "icon": "💇", "color": "#b45309",
      "panel": "פאנל 03 · 972-51-555-3333", "keywords": "שיער|גבות|זקן|השתל|קרקפת|נשיר|FUE" }
  ]
}
```

- `keywords: null` = בוט ברירת המחדל (מה שלא סווג נופל אליו) — שקול ל-fallback הקיים ל-treatments.
- סדר הבדיקה = סדר המערך (doctors לפני hair, כמו היום — "קורס הזרקות" לא יפול לשיער).
- עסק בלי `bots` בקונפיג → אין בורר, הדשבורד נראה ומתנהג בדיוק כמו היום. אפס השפעה על Dragons Kids ועסקים אחרים.
- ה-regex הקשיח ב-`getOverviewStats` נשאר כ-fallback לאסתטיק בלבד עד שהקונפיג נזרע; הלוגיקה קוראת קודם מהקונפיג.
- **חשיפה לפרונט:** מערך ה-`bots` (כולל keywords, לצורך הסיווג בצד לקוח) מצורף לתשובת `getBotSettings` הקיימת, שנטענת ממילא עם הדשבורד. אין אופרציה חדשה לצורך זה.

### UI — הבורר

- פס כרטיסים מתחת לכותרת (מעל טאבי הניווט): 🏠 **מרכז** + כרטיס לכל בוט (אייקון, שם, המספר המחובר).
- בחירת בוט: accent color של הבוט על הכותרת והכרטיס הפעיל, שם הבוט מוצג בכותרת הדשבורד. "מרכז" = ברירת מחדל = התצוגה המצרפית של היום.
- הבחירה נשמרת ב-state בלבד (לא URL, לא localStorage) — רענון חוזר למרכז. פשוט וצפוי בדמו.
- מובייל: הפס נגלל אופקית (אותו דפוס כמו טאבי הניווט).

### התנהגות פר-טאב כשבוט נבחר

| טאב | התנהגות |
|-----|---------|
| סקירה עסקית | `getOverviewStats` מקבל פרמטר אופציונלי `domain`; מסנן sessions אחרי הסיווג הקיים. כל האריחים (₪, שיחות, מענה, אחרי שעות, ברים יומיים) מחושבים על הבוט בלבד. הדונאט מוצג רק במרכז; בתצוגת בוט במקומו אריח "נתח מכלל הפניות" (X% · N שיחות). לחיצה על פלח בדונאט של המרכז מעבירה לבוט המתאים. |
| מרכז הלידים | סיווג ליד לבוט בצד לקוח לפי `ai_summary` + notes + תגיות, עם ה-keywords מהקונפיג. ליד שלא סווג → בוט ברירת המחדל. במרכז: כל הלידים עם תג-בוט קטן צבעוני על כל כרטיס. בתצוגת בוט: מסונן. מוני ה-KPI למעלה מסוננים בהתאם. |
| שאלות ותשובות | אותו סיווג client-side על שאלה+תשובה של כל פריט. פריט שלא מכיל אף מילת מפתח ייעודית = "משותף" — מופיע בכל הבוטים עם תג "משותף". במרכז רואים הכל עם תגי בוט. סטריפ ההצעות מסונן באותו אופן. |
| הגדרות | בתצוגת בוט: כרטיס "זהות הבוט" — שם, אייקון, המספר/פאנל המחובר, סטטוס חיבור (🟢 מחובר), מילות סיווג — שדות שם+פאנל+מילים ניתנים לעריכה ונשמרים ל-`dashboard_config.bots` דרך `POST /business/update` הקיים. מתחתיו ההגדרות הקיימות (מצב סוכן, שעות) עם באדג' "משותף לכל הבוטים". במרכז: כמו היום. |

### עקרון שמירת עקביות

הסיווג מחלק ואינו מסתיר: סכום שלושת הבוטים = המרכז, תמיד. ברירת המחדל בכל מסך היא "מרכז", שבו אין סיכון סיווג בכלל.

## פיצ'ר 2: ראיונות העשרת ידע

### אחסון

`business_profiles.draft_setup_data.interview` (JSONB, בלי מיגרציה):

```json
{
  "questions": [
    { "id": "iq_001", "bot": "doctors", "text": "האם הקורס מוכר לצורך גמול השתלמות?",
      "source": "curated", "status": "open",
      "raw_answer": null, "knowledge_item_id": null, "answered_at": null }
  ]
}
```

`status`: `open` / `answered` / `dismissed`. `source`: `curated` / `generated`. כשנבנה מודל הרב-בוטים האמיתי — עובר לטבלה.

### מאגר פתיחה

~8 שאלות לכל בוט (~24 סה"כ), מנוסחות כשאלות אמיתיות של מטופלים/רופאים מפורומים וקבוצות (ניסוח טבעי, לא "שאלון"). נזרעות לקונפיג של אסתטיק לפני הפגישה. שאלות מחיר נכללות בכוונה — הליטוש יפנה לניסוח שעומד בגדר "בלי מחירים בוואטסאפ".

### UI — כרטיס "שאלות מהשטח"

- בראש טאב שאלות ותשובות, מעל סטריפ ההצעות: כרטיס עם כותרת "שאלות מהשטח" וכיתוב "לקוחות שואלים את זה ברשת — ענו בשפה חופשית ונהפוך את זה לתשובה מוכנה במאגר".
- מציג עד 3 שאלות `open` של הבוט הנבחר (במרכז — מעורב מכל הבוטים, עם תג בוט). לכל שאלה: טקסטאריה למענה חופשי + "שלח" + "דלג".
- כפתור "✨ שלפו שאלות חדשות" בתחתית הכרטיס. בזמן שליפה — ספינר; נכשל — הודעה עדינה, המאגר הקיים ממשיך לתפקד.
- אין שאלות פתוחות → הכרטיס מציג רק את כפתור השליפה.

### אופרציות שרת חדשות (`server/lib/studio.js`, חשופות דרך `/studio/rpc` וה-portal whitelist)

1. **`getInterviewQuestions(businessId)`** — מחזיר את השאלות הפתוחות מה-JSONB.
2. **`answerInterviewQuestion(businessId, questionId, rawAnswer)`** —
   - שומר את `rawAnswer` על השאלה (לא הולך לאיבוד גם אם הליטוש נכשל).
   - קריאת Claude (Sonnet): מקבל את השאלה, התשובה הגולמית, פרופיל העסק וגבולות הסוכן (forbidden_claims / decision_logic); מחזיר `{question, answer, category}` מלוטשים בקול המותג. חוקים: לא ממציא עובדות שאין בתשובת הבעלים; מכבד גבולות (אצל אסתטיק — בלי מחירים, הפניה לנועה); שומר על השאלה קרובה למקור.
   - מכניס `knowledge_item` עם `suggested=true, is_active=false` → נוחת בסטריפ האישור הקיים.
   - מסמן את השאלה `answered` + מקשר `knowledge_item_id`.
   - ליטוש נכשל → השאלה נשארת `open` עם `raw_answer` שמור; ה-UI מציג "נסו שוב".
3. **`generateInterviewQuestions(businessId, bot)`** — קריאת Claude שמקבלת פרופיל עסק, שאלות ה-FAQ הקיימות וכל שאלות הראיון (בכל סטטוס), ומחזירה 3–5 שאלות חדשות בלי חפיפה, בסגנון "מה באמת שואלים ברשת". מצטרפות ל-JSONB כ-`source: "generated"`.

הקריאות ל-Claude משתמשות ב-`ANTHROPIC_API_KEY` הקיים ב-Railway env, באותו דפוס קריאה כמו הסוכן.

## בדיקות

- פיתוח ובדיקות מול עסק בדיקה ייעודי — **לא על אסתטיק** (כל צ'אט/פעולה בדיקתית מזהמת את הדמו; ראו ניקוי 2026-08-02).

- אחרי פריסה: זריעת הקונפיג לאסתטיק, מעבר מלא על הדמו בפרוד, ניקוי שאריות בדיקה.
